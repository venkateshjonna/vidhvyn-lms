
# 🔐 Google reCAPTCHA Integration (Human Verification)

This module adds **Google reCAPTCHA (v2 – “I’m not a robot”)** to the user registration flow to prevent bot registrations and automated abuse.

The verification is done **securely from the backend**, following industry standards.

---

## 📌 Why reCAPTCHA is required

Without CAPTCHA:

* Bots can submit registration forms
* Fake accounts get created
* Email system and database get abused

With CAPTCHA:

* Only **real humans** can register
* Backend confirms authenticity via Google
* Bot traffic is blocked **before database insertion**

---

## 🧠 High-Level Flow (End-to-End)

```
User opens Register page
↓
Google reCAPTCHA widget loads
↓
User clicks "I'm not a robot"
↓
Google generates a temporary token
↓
User submits registration form
↓
Backend sends token + secret key to Google
↓
Google responds with success = true / false
↓
If true → user registration continues
If false → registration blocked
```

## 🖥️ Frontend (register.html)

```html
<div class="form-group">
  <div class="g-recaptcha"
       th:attr="data-sitekey=${recaptchaSiteKey}">
  </div>
</div>

<script src="https://www.google.com/recaptcha/api.js" async defer></script>
```

### Explanation

* `g-recaptcha` class tells Google where to render CAPTCHA
* `data-sitekey` is the **public key** (safe to expose)
* Google JS automatically injects:

  ```html
  <input type="hidden" name="g-recaptcha-response">
  ```
* This hidden value is sent with form submission

## 🎯 Controller Layer

### GET: Load Registration Page

```java
@GetMapping("/register")
public String showRegister(Model model) {
    model.addAttribute("recaptchaSiteKey", recaptchaSiteKey);
    return "register";
}
```

**Purpose**

* Sends the public site key to the frontend
* Allows CAPTCHA widget to render correctly

---

### POST: Handle Registration

```java
@PostMapping("/register")
public String registerUser(
        @ModelAttribute RegisterDTO registerDTO,
        @RequestParam("g-recaptcha-response") String captchaResponse,
        Model model) {

    if (!recaptchaService.verify(captchaResponse)) {
        model.addAttribute("message", "Captcha verification failed. Please try again.");
        model.addAttribute("registerDTO", registerDTO);
        model.addAttribute("recaptchaSiteKey", recaptchaSiteKey);
        return "register";
    }

    userService.registerUser(registerDTO);
    model.addAttribute("message", "Registration successful");
    return "register";
}
```

### Explanation

* `g-recaptcha-response` is a **temporary token generated by Google**
* Backend never trusts frontend → verification required
* On failure:

  * Registration is blocked
  * User input is preserved
  * CAPTCHA reloads correctly

## 🔧 Service Layer (Backend Verification)

```java
@Service
public class RecaptchaServiceImpl implements RecaptchaService {

    @Value("${recaptcha.secret-key}")
    private String secretKey;

    @Value("${recaptcha.verify-url}")
    private String verifyUrl;

    private final RestTemplate restTemplate = new RestTemplate();

    @Override
    public boolean verify(String recaptchaResponse) {

        String url = verifyUrl +
                "?secret=" + secretKey +
                "&response=" + recaptchaResponse;

        RecaptchaDTO response =
                restTemplate.postForObject(url, null, RecaptchaDTO.class);

        return response != null && response.isSuccess();
    }
}
```

### What happens here?

* Backend sends an **HTTP POST request** to Google
* Includes:

  * `secret` → proves backend ownership
  * `response` → token generated by CAPTCHA
* Google validates and returns JSON
* Spring converts JSON → Java DTO
* Only `success = true` allows registration

📌 This is a **server-to-server call**
Frontend cannot fake this request.

## 📦 RecaptchaDTO

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class RecaptchaDTO {
    private boolean success;
    private String challenge_ts;
    private String hostname;
}
```

### Purpose

* Maps Google’s JSON response
* `success` determines human vs bot
* Other fields are useful for logging/debugging

## ⚙️ Configuration (`application.properties`)

```properties
recaptcha.site-key=YOUR_PUBLIC_SITE_KEY
recaptcha.secret-key=YOUR_PRIVATE_SECRET_KEY
recaptcha.verify-url=https://www.google.com/recaptcha/api/siteverify
```

🔐 **Important**

* `site-key` → frontend
* `secret-key` → backend only
* Never expose secret key to client

---

## 🛡️ Security Notes

* CAPTCHA is validated **before database operations**
* Bots cannot bypass backend verification
* Even direct HTTP requests are blocked
* Passwords are never re-filled on failure

---

## 🧪 Common Failure Scenarios

| Cause               | Result                     |
| ------------------- | -------------------------- |
| CAPTCHA not clicked | Verification fails         |
| Invalid token       | Registration blocked       |
| Wrong secret key    | Google rejects request     |
| Internet down       | CAPTCHA verification fails |
